# Image Builder Integration for Avahi mDNS with Unique Hostnames

## Date: 2026-08-18

## Overview
This document describes the changes needed in `/fabmo_image_builder/build-fabmo-image.sh` to integrate Avahi mDNS with dynamic unique hostnames.

## Strategy

**Two-tier approach:**
1. **Image builder**: Pre-installs Avahi package and service file
2. **Updater patch**: Generates unique hostname config on first boot

This ensures each tool gets its unique hostname based on actual hardware ID.

---

## Required Changes to build-fabmo-image.sh

### 1. Package Installation

**Location**: In the `install_packages_and_configure()` function (around line 42)

**Add to package list:**
```bash
apt-get install -y \
    ... \
    avahi-daemon \
    avahi-utils
```

**Rationale**: Pre-installs Avahi so patch doesn't need to apt-get during first boot (faster).

---

### 2. Service File Installation

**Location**: In the file copying section (around line 200-220)

**Add this block:**
```bash
# Avahi mDNS - Install service file
# Note: avahi-daemon.conf will be dynamically generated by patch 003 on first boot
# using unique machine ID to create hostname like fabmo-a1b2c3.local
if [ -f "$RESOURCE_DIR/avahi/fabmo.service" ]; then
    install_file "$RESOURCE_DIR/avahi/fabmo.service" "/etc/avahi/services/fabmo.service"
else
    echo "⚠️  Warning: Avahi service file not found in resources"
fi
```

**DO NOT copy avahi-daemon.conf** - It's generated dynamically by the patch

---

### 3. Service Enablement

**Location**: In the `load_and_initialize_systemd_services()` function (around line 550)

**Add to service list:**
```bash
systemctl enable avahi-daemon.service
```

**Rationale**: Ensures Avahi starts on boot and is ready for patch customization.

---

## Resource Files Needed

**In** `/fabmo_image_builder/resources/avahi/`:

```
resources/
└── avahi/
    └── fabmo.service       # HTTP service advertisement file
```

**Source**: Copy from `/fabmo-updater/patches/resources/003-avahi/fabmo.service`

**Content of fabmo.service:**
```xml
# FabMo mDNS Service Configuration
# Advertises fabmo-XXXXXX.local on the network for easy access
# Allows users to access FabMo without knowing IP address
# Especially useful for direct connections with static IP conflicts

<?xml version="1.0" standalone='no'?>
<!DOCTYPE service-group SYSTEM "avahi-service.dtd">
<service-group>
  <name replace-wildcards="yes">FabMo on %h</name>
  <service>
    <type>_http._tcp</type>
    <port>80</port>
    <txt-record>path=/</txt-record>
  </service>
  <service>
    <type>_fabmo._tcp</type>
    <port>80</port>
    <txt-record>version=2.0</txt-record>
    <txt-record>model=FabMo Engine</txt-record>
  </service>
</service-group>
```

## What Happens on First Boot

### Image Build Time
1. Image builder installs `avahi-daemon` and `avahi-utils` packages
2. Copies `fabmo.service` to `/etc/avahi/services/`
3. Enables `avahi-daemon.service` (but doesn't start it yet)
4. **No hostname config** (will be generated on first boot)

### First Boot
1. System boots with default Avahi config (if any)
2. FabMo updater starts
3. **Patch 003 runs automatically:**
   - Gets machine ID via `hooks.getUniqueID()` (e.g., `a1b2c3d4e5f6`)
   - Extracts first 6 chars: `a1b2c3`
   - Generates hostname: `fabmo-a1b2c3`
   - Writes `/etc/avahi/avahi-daemon.conf` with unique hostname
   - Restarts `avahi-daemon.service`
   - Tests resolution: `fabmo-a1b2c3.local`
4. Tool is now accessible at `http://fabmo-a1b2c3.local`

## Testing the Integration

### After Building Image

**1. Flash SD card and boot Raspberry Pi**

**2. Check Avahi package is installed:**
```bash
dpkg -l | grep avahi
# Should show: avahi-daemon, avahi-utils
```

**3. Check service file is present:**
```bash
ls -la /etc/avahi/services/fabmo.service
# Should exist
```

**4. Check service is enabled:**
```bash
systemctl is-enabled avahi-daemon
# Should output: enabled
```

**5. Wait for updater to apply patches (watch logs):**
```bash
tail -f /var/log/fabmo/fabmo-updater.log | grep -i avahi
```

**6. Verify unique hostname was generated:**
```bash
grep host-name /etc/avahi/avahi-daemon.conf
# Should show: host-name=fabmo-XXXXXX
```

**7. Test mDNS resolution:**
```bash
# Get your hostname
HOSTNAME=$(grep host-name /etc/avahi/avahi-daemon.conf | cut -d= -f2)
echo "Testing: ${HOSTNAME}.local"

# Resolve hostname
avahi-resolve -n ${HOSTNAME}.local
# Should output: fabmo-XXXXXX.local    192.168.X.X

# From client device
ping ${HOSTNAME}.local
curl http://${HOSTNAME}.local
```

## Benefits of This Approach

### ✅ Fast First Boot
- Avahi already installed (no apt-get delay)
- Patch only writes one config file and restarts service

### ✅ Unique Hostnames
- Each tool gets unique, predictable hostname
- Multiple tools on same network don't collide
- Matches AP naming convention: `FabMo-A1B2C3` → `fabmo-a1b2c3.local`

### ✅ Automatic Customization
- No manual configuration needed
- Hostname based on actual hardware ID
- Works for all platforms (RPi, BeagleBone, Edison, etc.)

### ✅ Dual Coverage
- **New images**: Pre-installed, customized on first boot
- **Existing systems**: Patch installs and configures everything
- **Future updates**: Patch verifies and maintains config
